## Instructions

Review the changes made in this PR by examining the diff. Focus on:

1. **Correctness** — Does the implementation match the plan and ticket requirements?
2. **Code Quality** — Are there maintainability, readability, or design issues?
3. **Security** — Are there any security vulnerabilities introduced?
4. **Edge Cases** — Are important edge cases handled?
5. **Performance** — Are there obvious performance concerns?

## Output Format

For each finding, classify its severity and output it in this exact format:

- `CRITICAL: <description>` — Bugs, security vulnerabilities, data loss risks. These MUST be fixed.
- `MAJOR: <description>` — Significant design flaws, missing error handling, or logic errors that should be addressed.
- `MINOR: <description>` — Style issues, naming suggestions, small improvements. These are nice-to-have.
- `NOTE: <description>` — Observations, questions, or suggestions for future consideration.

If there are no critical or major findings, state exactly:
No critical or major findings.

Always end with a brief summary of the overall quality of the changes.
