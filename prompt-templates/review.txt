<instructions>
Review the changes made in this PR by examining the diff. Focus on:

1. Correctness -- Does the implementation match the plan and ticket requirements?
2. Code Quality -- Are there maintainability, readability, or design issues?
3. Security -- Are there any security vulnerabilities introduced?
4. Edge Cases -- Are important edge cases handled?
5. Performance -- Are there obvious performance concerns?

After completing your review, post your findings as a comment on the GitHub PR.
If a PR URL is available ({{pr_url}}), run:
  gh pr comment {{pr_url}} --body "<your full review output formatted in markdown>"
If no PR URL is available, skip the posting step.
</instructions>

<output_format>
Classify each finding by severity using these exact prefixes:

- CRITICAL: <description> -- Bugs, security vulnerabilities, data loss risks. MUST be fixed.
- MAJOR: <description> -- Significant design flaws, missing error handling, logic errors.
- MINOR: <description> -- Style issues, naming suggestions, small improvements.
- NOTE: <description> -- Observations, questions, or suggestions for future work.

If there are no critical or major findings, state exactly:
No critical or major findings.

IMPORTANT: The pipeline detects "CRITICAL:" and "MAJOR:" to determine pass/fail.
If you include ANY line starting with "CRITICAL:" or "MAJOR:", the stage will fail
and the pipeline will revert to the Implement stage.

Always end with a brief summary of overall change quality.

End your output with a status declaration:
STATUS: done     -- if no critical/major findings (review passed)
STATUS: retry    -- if critical/major findings found (will revert to Implement)
STATUS: failed   -- if review could not be completed
</output_format>

<examples>
Good findings (specific, actionable):
- CRITICAL: SQL query in `src/db.ts:45` concatenates user input directly -- SQL injection vulnerability.
- MAJOR: The `deleteUser()` function has no authorization check -- any authenticated user can delete any other user.
- MINOR: Variable name `x` in `utils.ts:12` is unclear -- consider renaming to `retryCount`.
- NOTE: The `formatDate()` helper could be extracted to a shared utilities module for reuse.

Bad findings (vague):
- CRITICAL: Security issues exist.
- MAJOR: Code quality could be better.
</examples>
