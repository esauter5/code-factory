<examples>
Good acceptance criteria (mechanically verifiable):
- "GET /api/users returns 200 with JSON array"
- "Running `pnpm lint` produces zero errors"
- "The `status` column exists in the tasks table with default value 'pending'"
- "Clicking the delete button shows a confirmation dialog"

Bad acceptance criteria (vague, not verifiable):
- "Works correctly"
- "Good performance"
- "Handles edge cases properly"
- "User can interact with it easily"
